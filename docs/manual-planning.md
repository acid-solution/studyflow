# 手动创建目标和学习计划

目标页回答“想达成什么”；学习计划负责把其中一项结果落实成具体路线。目标可以包含分目标和多份并行计划，不要求每个目标都先拆分。

## 从目标开始

1. 点击“新建目标”，填写目标名称。完成标准、目标日期和说明均可选。
2. 不选所属目标时创建顶层目标；选定已有目标时创建分目标。选择器显示完整路径，编辑时排除自身及后代，避免选错层级。
3. 在目标卡片直接点击“添加计划”，所属目标自动带入；也可以先“新增分目标”。编辑、确认完成和放弃放在“更多”菜单中。

## 从学习计划开始

1. 点击“新建计划”，选择所属目标，填写计划名称和计划目标；可展开填写完成标准、目标日期和说明。
2. 没有目标时，可以在当前弹窗中新建目标。保存后回到原计划，保留已经填写的内容并选中新目标。
3. 下一步选择“按日期安排”或“按课时推进”，填写每周预计投入（小时）。起止日期可选，只表示参考周期，不自动生成或排期任务。
4. 点击“创建并安排任务”，服务端创建计划及 V1 草稿，页面直接打开草稿编排。返回上一步保留表单内容；最终提交前不创建计划。

每周投入在前端以小时填写，提交时转换为整数分钟。目标日期属于计划；参考周期、投入预算和推进方式属于计划版本。

## 编排和开始执行

- 可以先添加具体任务，也可以先添加阶段，再从阶段卡片直接添加任务。阶段内入口自动带入所属阶段。
- 阶段可填写预期成果；任务可填写说明和预计分钟数。勾选“保存后继续添加”可以连续录入，并明确提示上一项已保存。
- 日期任务允许暂不安排日期；课时任务不显示日期字段。保存任务不会自动启用草稿。
- 草稿页显示“目标已确定 → 添加阶段与任务 → 确认后启用版本”的引导。用户主动激活版本后，任务进入今日、按课时等执行视图。
- 版本设置和空白版本创建使用表单，不要求输入内部模式名称。
- 每次保存都是一次独立业务操作；创建计划、添加阶段、添加任务分别持久化。中途离开时，已经保存的草稿仍可在学习计划页继续编排。

## 编辑保护与错误处理

- 请求中禁用提交，阻止连续点击重复创建；请求失败显示原因并保留输入。
- 关闭有未保存内容的目标、计划或任务表单时提示确认；弹窗限制键盘焦点并恢复原焦点，窄屏下内容滚动、底部操作保持可见。
- 编辑目标时保留原乐观锁版本；其他客户端修改后提示重新核对，不覆盖输入或偷换版本号。
- 添加任务期间，计划或计划版本变为只读、阶段被删除或推进方式改变时，保留输入并阻止继续保存。

自动化回归见 `frontend/src/CreationFlow.test.tsx`，覆盖首次建目标、两步创建、返回和失败恢复、重复提交、层级选择、跨客户端变更保护以及两类任务录入。

## 放弃与默认选择

- 默认采用“每次询问”。点击放弃目标或计划时，显示应用内确认弹窗，以中文勾选“从上层完成判断中排除”或“仍作为必要子项，继续阻塞上层”；两个选项互斥。顶层目标不需要选择上层处理方式。
- 勾选“以后按此选择直接放弃，不再弹窗”并确认后，把本次选择保存为当前账号的偏好。此后点击放弃会直接执行，不再显示弹窗；该偏好对目标与计划共用，其他设备也使用同一设置。
- 在“设置 → 放弃操作”中，可以改为默认排除、默认阻塞，或恢复每次询问。设置只影响今后的操作，不修改已经放弃的内容。
- 放弃保留内容和执行记录；放弃目标不会连带放弃下属目标或计划。根目标没有上层处理方式，但存在账号默认时也跳过确认。
- 放弃失败时保留本次选择，不保存新的默认值。如果放弃成功而偏好保存失败，明确提示用户到设置中重试，不重复执行放弃操作。
- 读取偏好失败时停止操作并允许重试，不猜测用户是否已经同意跳过确认。

`GET/PATCH /api/v1/preferences` 的 `default_abandon_parent_effect` 取值为 `ask`（每次询问）、`exclude`（默认排除）或 `block`（默认阻塞）。数据库升级为已有用户设置 `ask`，不会自动替用户开启直接放弃。
