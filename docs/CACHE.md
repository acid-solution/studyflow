# 聚合读缓存与恢复

核对日期：2026-10-17。Redis 加速聚合读，MySQL 保持业务事实与约束。核心实现为 [Redis 适配](../internal/cache)、[应用缓存边界](../internal/studyflow/cache.go)。

## 缓存范围

目标树、无筛选的基础任务列表和周报聚合使用缓存；今日工作台复用基础任务查询。带筛选列表直接查询数据库，避免大量近似缓存键。计划详情及业务写入不依赖缓存。

幂等回执、单账号运行计时约束、计划与任务数据留在 MySQL。缓存丢失只能造成回源，不应造成重复导入或多个计时。

## 代数与条件回填

每个账号的代数进入缓存 key：

~~~text
sf:v1:gen:<user_id>
sf:v1:goaltree:<user_id>:<gen>
sf:v1:tasklist:<user_id>:<gen>
sf:v1:review:<user_id>:<week_start>:<gen>
~~~

业务写入成功后推进用户代数，旧 key 随即不再用于当前读取，无需逐个枚举删除。查询回填用 Lua 比较代数仍相同，避免“读库期间发生写入，旧结果最后回填”的污染。

周报 key 使用解析后的周起始日，跨周不会继续命中上周“本周”结果。

## 故障与隔离

Redis 超时、连接失败、解码失败或无法确认代数时回源 MySQL，代数未知不能当成真实的 0。每次 Redis 操作有 200ms 超时。

数据库写入成功但缓存失效无法确认时，进入隔离期。Redis 恢复连接后仍继续回源，直到旧数据安全窗口过去；服务启动也采用同样保护。后台每 15 秒检查连通性和隔离结束条件。

缓存数据默认 TTL 30 秒，带 ±10% 抖动。代数 key 的 TTL 为数据 TTL 两倍，在读取、推进和成功回填时续期，确保其晚于受保护数据过期。

## 配置

`CACHE_ENABLED=false` 完全使用 MySQL。程序默认关闭，配置示例和 Compose 可开启。`REDIS_ADDR`、`REDIS_DB`、`REDIS_PASSWORD`、`CACHE_TTL` 见[开发指南](DEVELOPMENT.md)。

自带 Compose Redis 无密码且不持久化，不能配置一个服务端不存在的密码。Redis 恢复与业务成功分别观察，不以缓存健康代替数据库约束。
