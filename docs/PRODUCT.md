# StudyFlow 产品与使用说明

现行版本：2026-10-17。StudyFlow 帮助用户明确结果、组织执行方案、记录投入和复盘。它不根据任务勾选自动判定知识掌握，也不自动替用户安排每天的具体时刻。

## 从目标开始

用户在目标页创建顶层目标或分目标。目标包含名称，可选完成标准、目标日期和说明。目标可以继续拆分，也可以直接挂多份并行计划；移动时不能形成循环。

例如“准备开发实习”可以同时包含“完成主项目”和“补足基础”的计划。目标是要实现的结果，计划是围绕其中一项结果组织的安排，两者分别保留完成状态。

## 创建计划与草稿

新建计划先选择所属目标，填写计划名称与必填计划目标；完成标准、目标日期和说明可选。缺少目标时可以在原表单中新建，并保留已填内容。

下一步选择按日期或按课时，填写每周预计投入，可选参考起止日期。最终提交创建计划和 V1 草稿，然后进入编排。起止日期不会自动生成任务；每周投入在页面以小时输入，服务端保存分钟。

具体弹窗、连续添加任务和错误恢复见[手动规划](manual-planning.md)。

## 版本与日常执行

每个计划版本拥有独立的模式、阶段、任务和进度。用户可创建空白版本，也可复制任意既有版本。复制保留任务当前状态，不复制计时和改期事件；复制后双方互不联动。

草稿确认后才激活。一个计划当前只有一个选用版本，切换历史版本使用它原有进度。正在计时时需要先结束计时，历史版本、已取消草稿和已结束计划继续保留阅读边界。

首页按逾期、今天、按课时、未来组织任务。日期任务可以暂不安排日期；课时任务按顺序推进，不能设置安排日期。用户可以完成、重新打开、取消任务或修改日期。

## 投入与复盘

计时由服务端记录开始和结束，每个账号同时只有一个运行中计时。完成正在计时的任务时自动结束该计时；误开记录可丢弃。

周报按用户时区和周起始日汇总完成数、预算、实际投入、按期情况、逾期和改期等。计时结束不等于任务完成，任务完成不等于计划目标达成。

## 达成、放弃与恢复

计划和目标的达成由用户分别确认。父目标的摘要只看直属分目标和直属计划，系统提供判断依据，不自动把父目标标为达成。

放弃保留内容和历史，不级联放弃所有后代。放弃项可以继续阻塞上层，也可以从上层判断排除。默认每次询问；用户明确保存默认后，后续按账号偏好直接操作。恢复嵌套项需先恢复祖先。

字段、状态与边界案例见[领域规则](../STUDYFLOW_V2_PLAN.md)。

## 导入计划

网页支持粘贴计划草稿、核对摘要后确认导入，重复确认重放原结果。HTTP 与 MCP 均通过同一服务写入。

JobPilot 路线导入首次创建一个目标及项目实践、知识准备两份草稿；后续只为变化的计划新增草稿。已有草稿要先激活或取消。导入后仍需登录 StudyFlow，并主动激活。详见[路线导入](learning-route-import.md)。

## 多端与编辑保护

同一账号的其他页面修改数据后，当前页面通过 SSE 收到变更通知并刷新。未保存的表单保留原输入与旧版本号，提示用户核对，不能以新版本号悄悄覆盖他人更新。断线恢复遵守日志保留窗口，见[通知](notifications.md)。

## 当前范围

已包含真实业务 API、MySQL 持久化、共享认证、计划版本、MCP 导入、聚合缓存和多端同步。当前不提供模型自动规划、全天日历排程、自动能力评分或通用消息中心；这些不属于已有功能承诺。

产品使用、领域约束与技术验证分别维护。运行步骤见[开发指南](DEVELOPMENT.md)，可重复验收见[验证指南](VALIDATION.md)。
